--- What this says, and what it does not
#
# Verified: F-4's failure case is fixed. A board that boots with no host reading
# is greeted with `BOOT,...` as the first line when a host attaches later - seen
# on attach 1 and attach 3, from a boot whose first sample proves nobody was
# attached during the boot wait.
#
# Not verified, and observed the other way: the code re-arms the greeting on a
# host-attach *transition*, and attach 2 shows no transition was seen - the boot
# line was not re-sent, and the telemetry stream resumed mid-flight with current
# records. The host-presence signal is the USB CDC `connected()` predicate (DTR),
# and why the detach between attach 1 and attach 2 was not observed is NOT
# determined: the port was closed by the capturing process, and whether the host
# stack deasserted DTR (and when) was not measured. Attach 3 then behaved as
# attached-again, so the signal does flap sometimes.
#
# Consequence for the record: the honest statement is "the boot line is sent once
# per boot, to the first host that attaches, whenever it attaches". A greeting per
# attach is what the code intends but it is NOT demonstrated here, and it is not
# claimed. Nothing in this file is a claim about a second image or another host
# machine, and no motor supply was connected (USB only).
